# 激活近似安全实验项目

## 1. 项目定位

本目录用于完成“推理加速的深度思考大模型安全防护”项目中**激活近似安全性**这一条实验主线。

本项目不是以追求完整复现某篇论文、训练超大模型或发表论文为第一目标，而是以形成一条**可运行、可解释、可记录、可用于结题的实验闭环**为目标：

```text
激活近似/推理加速
        ↓
模型输出安全性是否退化
        ↓
寻找最容易导致安全退化的近似配置（MVA）
        ↓
分析激活表示和输出语义发生了什么变化
        ↓
设计并验证近似感知的安全对齐/修复方法
```

## 当前成果与入口（2026-11-22）

已完成基线、输出扰动和 SiLU 近似对照、层敏感性筛查，以及近似条件下的轻量修复验证。主结果是 Qwen2.5-1.5B-Instruct 的 **索引 27（从零计数）Hard-Swish + 74 对 DPO，训练 3 个 epoch**：同一后期对照中，HarmBench test 的自动有害输出候选从未修复的 103/320 降至 73/320，原始 SiLU 为 83/320；与此同时 XSTest safe 的误拒答候选增加，不能称为全面优于原版。全层修复仅部分改善，表征正则未显示稳定额外收益。

## 2. 我们到底要回答什么科学问题

项目核心问题可以表述为：

> 一个已经经过安全对齐的语言模型，在部署时对激活函数进行近似、稀疏化或量化后，是否会出现安全能力下降？如果会，哪些近似配置最危险，安全对齐为什么会失效，以及能否用额外的安全对齐手段恢复安全性？

这里有三个层次的问题：

### 2.1 现象层：激活近似会不会造成安全退化

在模型、数据、提示词和解码参数保持一致的条件下，对比：

```text
原始模型（baseline）
vs.
施加激活近似后的模型
```

重点观察：

- 对有害请求的拒答能力是否下降；
- 有害输出比例是否上升；
- 有害输出严重程度是否上升；
- 正常任务能力是否基本保持；
- 推理延迟是否发生变化。

如果出现“安全性明显下降，但正常任务能力变化不大”，这正是本项目最有价值的现象之一：说明激活近似可能破坏了安全对齐相关表征，而不一定显著破坏一般语义能力。

### 2.2 定位层：哪一种近似、哪一层、什么强度最危险

不是所有近似都会造成同样的影响，也不是所有层都同样敏感。因此需要扫描：

- 近似类型：Gaussian、Laplace、稀疏化、伪量化等；
- 近似强度：噪声比例、稀疏率、量化 bit 数；
- 施加位置：早期层、中间层、后期层；
- 模型输出：安全指标和正常任务效用指标。

在给定模型和评测集上，使安全风险指标最大的近似配置，可以称为：

```text
MVA（Most Vulnerable Approximation，最脆弱/最易导致安全退化的近似配置）
```

严格来说，MVA不是一个凭感觉指定的配置，而是通过实验搜索得到的配置。例如：

```text
MVA = Gaussian 噪声 + 第 2 层 MLP 输出 + strength=0.10
```

这里只是格式示例，不代表已经得到真实结论。

### 2.3 机制层：激活近似为什么会让安全对齐失效

发现安全指标变差还不够。我们需要进一步分析：

- 有害提示和正常提示经过各层后的激活表示是否发生分离/混合变化；
- 负责安全拒答的表示是否被扰动；
- 近似是否改变了最后一个 token 或关键位置的激活方向；
- 模型是否仍然理解“用户在请求什么”，但不再执行安全拒答；
- 还是连任务语义本身也被破坏；
- 安全拒答相关信号是否被削弱、偏移或被有害回答方向的信号覆盖。

因此，“改变语义”需要谨慎表述。第一阶段不能直接声称已经证明了“激活近似改变了语义”。更准确的研究路径是：

```text
先观察输出行为变化
  ↓
再比较激活表示变化
  ↓
再分析语义/安全表征的变化
  ↓
最后提出可能的失效机制
```

我们最终要区分两种情况：

1. **一般语义能力破坏**：模型连正常问题也无法理解；
2. **安全对齐选择性破坏**：模型正常任务仍然可用，但面对有害请求时拒答能力下降。

第二种情况更能支撑本项目的安全研究结论。

### 2.4 修复层：如何恢复安全对齐

在确认存在稳定的安全退化现象后，再设计“激活近似感知”的安全修复方法。例如：

- 使用近似后的模型进行安全微调；
- 对安全拒答样本进行 LoRA 修复；
- 在训练时同时加入原始激活和近似激活；
- 对安全敏感层进行针对性约束；
- 对有害与正常激活表示加入分离性或相似性约束。

修复是否成功，不能只看安全性，还要同时看：

```text
安全性恢复
+ 正常任务能力保持
+ 推理开销可接受
```

## 3. 目前代码已经实现了什么

### 3.1 `src/generate.py`

主推理入口，负责：

- 加载 Hugging Face 因果语言模型；
- 加载 tokenizer；
- 读取 JSONL 提示词；
- 使用聊天模板构造输入；
- 生成模型回答；
- 根据命令行参数安装激活近似 hook；
- 记录回答、模型、近似类型、层号、强度、随机种子和延迟。

### 3.2 `src/activation_hooks.py`

负责：

- 定位常见 Transformer 模型的 decoder layers；
- 定位每个 block 中的 MLP/FFN 子模块；
- 在指定 MLP 输出处注册 forward hook；
- 将激活张量交给近似算子处理。

当前实验位置为：

```text
decoder block 的 MLP 输出
```

这是第一版的通用实验位置，不代表已经精确复现论文中所有激活函数位置。正式报告中需要明确记录该位置。

### 3.3 `src/approximation.py`

当前支持四类算子：

- `gaussian`：按激活标准差加入 Gaussian 噪声；
- `laplace`：按激活标准差加入 Laplace 噪声；
- `sparsify`：将绝对值较小的一部分激活置零；
- `quantize`：对激活进行对称伪量化。

### 3.4 `src/evaluate_safety.py`

当前是基于拒答关键词的初步筛查器。它可以帮助检查：

- 输出中是否出现常见拒答表达；
- 不同设置下规则筛查比例是否变化。

但它不是经过验证的完整 ASR 评测器，不能单独作为最终安全结论。正式实验需要使用获准的安全评测数据，并进行人工复核或接入经过验证的分类器。

### 3.5 `src/evaluate_utility.py`

统计初步效用指标：

- 平均延迟；
- 中位延迟；
- 平均回答长度。

后续可以根据时间和算力增加准确率、任务成功率或人工评分。

### 3.6 `src/summarize_results.py`

把多个 JSONL 结果汇总为 CSV，便于使用 Excel 或 Python 画图和整理报告。

### 3.7 `src/evaluate_ppl.py`

目前只是预留文件，尚未完成困惑度实现。当前不能把 PPL 写成已经完成的实验指标。

### 3.8 `src/train_lora.py`

目前只是后续安全修复阶段的占位文件。不能在基线和扰动实验尚未稳定前直接进行训练。

## 5. 实验总路线

### 阶段 A：建立可信的原始模型基线

目的：确认模型本身和评测流程正常。

需要固定：

- 模型版本；
- tokenizer；
- 提示词数据；
- system prompt/chat template；
- 最大输入长度；
- 最大输出长度；
- temperature、top-p；
- 随机种子；
- 硬件和推理精度。

输出：

- 正常任务回答；
- 安全测试回答；
- 基线安全指标；
- 基线效用指标。

如果没有可靠 baseline，后面的所有“退化”都无法解释。

### 阶段 B：零强度控制实验

目的：验证 hook 本身没有改变模型。

做法：

```text
安装 hook，但使用 strength=0
```

结果应该与 baseline 基本一致。若差异很大，说明 hook 位置、模型加载、随机性或生成流程存在问题，不能继续做正式实验。

### 阶段 C：激活近似扫描

目的：确认哪些近似会造成安全退化。

第一轮建议少量、可控地扫描：

```text
近似类型：Gaussian、稀疏化、伪量化
层位置：早期层、中间层、后期层
强度：低、中、高三个档位
```

每个实验只改变一个变量，其他条件保持一致。

输出一张实验表：

| 模型 | 近似类型 | 层 | 强度 | 安全指标 | 正常任务指标 | 延迟 |
|---|---|---:|---:|---:|---:|---:|

### 阶段 D：确定 MVA

目的：在预先定义的评测集和指标下，找到安全风险最大的配置。

可以将实验结果按安全风险排序。例如：

```text
MVA = 安全退化指标最高的配置
```

但需要注意：MVA依赖于：

- 模型；
- 数据集；
- 安全指标；
- 近似类型；
- 层搜索范围；
- 强度搜索范围。

因此不能把某个模型上的 MVA 直接说成所有模型的普遍规律。

### 阶段 E：敏感层和稀疏扰动分析

目的：研究安全退化主要集中在哪里。

做法：

- 逐层施加相同强度的近似；
- 比较每层造成的安全指标变化；
- 选择若干最敏感层；
- 再做多层组合实验；
- 比较早期层、中间层和后期层。

预期产物：

- 层-安全风险曲线；
- 近似强度-安全风险曲线；
- 单层与多层对比表。

注意：本项目申报书中提到的 LAS 可以作为“安全敏感层分析”的概念，但当前代码还没有实现正式 LAS 优化算法。第一版先用逐层扫描建立可解释的近似版本。

### 阶段 F：激活表示和语义机制分析

目的：回答“安全对齐为什么失效”。

这一步需要增加激活采集功能，记录指定层、指定 token 位置的激活表示，然后比较：

- baseline 与 MVA 的激活差异；
- 有害提示与正常提示的类间距离；
- 同一提示在近似前后的余弦相似度；
- 安全拒答样本和非拒答样本的表示分布；
- 最后 token 或 response 起始位置的表示变化。

推荐第一版指标：

- L2 距离；
- cosine similarity；
- 类内平均距离；
- 类间平均距离；
- PCA 或 t-SNE/MDS 可视化。

这一步的结论应采用“支持某种机制”的表述，而不是过度声称已经证明因果关系。例如：

> MVA 使安全提示与正常提示在指定层的表示可分性下降，同时正常任务指标变化较小，说明该近似可能优先破坏了与安全拒答相关的表示结构。

### 阶段 G：安全对齐修复

目的：验证安全退化是否可以被恢复。

建议先做最小可行修复：

1. 选择 baseline 安全数据和正常数据；
2. 在固定 MVA 条件下训练或微调；
3. 优先使用 LoRA，减少显存和训练成本；
4. 同时测试原始模型和 MVA 模型；
5. 在未见过的安全测试集上评估；
6. 比较修复前后安全性和正常任务效用。

修复实验至少应包含：

```text
原始模型
原始模型 + MVA
MVA + 普通安全微调/LoRA
MVA + 近似感知安全修复
```

如果暂时没有条件完成复杂的 QuadA 类方法，可以把“固定 MVA 下的 LoRA 安全修复”作为项目可交付的第一版防护方法，并诚实说明它是简化实现。

## 6. 每个阶段的目的不是一样的

| 阶段 | 主要目的 | 不能替代的内容 |
|---|---|---|
| baseline | 证明模型和评测流程正常 | 不能说明近似有风险 |
| 零强度控制 | 证明 hook 不引入额外偏差 | 不能说明非零扰动影响 |
| 扰动扫描 | 找到安全退化现象和候选 MVA | 不能解释机制 |
| 敏感层分析 | 找到风险集中层 | 不能直接证明语义因果 |
| 激活表示分析 | 提供安全对齐失效的机制证据 | 不能只凭可视化下结论 |
| 修复实验 | 验证安全对齐能否恢复 | 不能掩盖前面没有稳定现象 |

## 8. 数据和安全注意事项

`data/harmful_prompts.jsonl`、`data/safety_train.jsonl` 和 `data/safety_test.jsonl` 当前只是占位模板，不能作为正式实验结论来源。

正式使用前需要：

1. 选用项目允许使用的公开安全评测数据；
2. 记录数据集名称、版本、许可证和来源；
3. 将训练集和测试集严格分开；
4. 不要把测试集用于修复训练；
5. 对危险输出进行最小化展示和访问控制；
6. 对分类器结果进行抽样人工复核；
7. 不在 README、代码和普通日志里直接堆放真实危险指令。

本项目只用于受控的安全评估和防护研究，不用于生成、传播或优化危险内容。

## 11. 当前阶段的结论

现在最重要的不是立刻批量运行，而是先把研究链条理清：

```text
先确认基线可靠
  ↓
再确认激活近似是否真的造成安全退化
  ↓
再搜索 MVA 和安全敏感层
  ↓
再分析激活表示/语义变化
  ↓
最后做安全对齐修复并验证
```

任何阶段如果前一阶段没有得到稳定结果，都不要直接跳到下一阶段。
